# Avatars Everywhere Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Users upload an avatar with the same validation the entry photo upload already has, and the avatar (or a consistent fallback) shows everywhere a user is rendered: feed cards, leaderboard, profile header, friends list, and the home nav.

**Architecture:** The avatar upload endpoint (`POST /me/avatar`) already exists but skips the size/type validation the entry photo endpoint has. Phase 1 extracts that validation into one shared module and applies it to both endpoints, then makes the friendships list carry signed avatar URLs like every other user-bearing endpoint. Phase 2 adds one `Avatar` component (image or initial fallback) and uses it at every render site, plus one shared client-side file check used by both the avatar picker and the log form. Phase 3 ships through `/ship`.

**Tech Stack:** NestJS 11 + Drizzle (api/), Next.js 16 App Router + TanStack Query + Tailwind (web/), Supabase Storage (private `photos` bucket, signed URLs), Jest + supertest (api), Vitest + Testing Library (web).

**Spec:** Inline — see "Spec" below. No separate document.

## Spec

User request (verbatim): "setting up avatar urls where they can upload avatars. and wherever the places where user shows up and leaderboard or whatever it should show up there, there should be validation on uploading and whatnot make sure to reuse it. Finally test your code and use /ship."

Current state (read before planning):
- `api/src/profiles.controller.ts` `POST /me/avatar`: stores `{userId}/avatar.jpg` with `upsert: true`, sets `profiles.avatar_url` to that path. **No file size limit, no content-type check.**
- `api/src/entries.controller.ts` `POST /entries/:id/photo`: `FileInterceptor('file', { limits: { fileSize: 5 MiB } })` + `ParseFilePipe([FileTypeValidator('image/jpeg')])`. Tested by `api/src/entries-photo.spec.ts`.
- Signed `avatar_src` is already attached by `/me`, `/profiles/:username`, `/feed`, `/entries` (via `entry-rows.ts`), `/leaderboard`. **Not** by `/friendships`.
- Web render sites with an inline `<img>` only when `avatar_src` is set (nothing otherwise): `web/app/entry-card.tsx`, `web/app/board/board.tsx`, `web/app/u/[username]/profile-view.tsx`. Sites that render a username with no avatar at all: `web/app/friends/page.tsx` (three lists), `web/app/page.tsx` (home nav link).
- `web/app/account-panel.tsx`: `<input type="file" accept="image/*">` uploads on change through `compressPhoto` + `photoForm` from `web/lib/photo.ts`. No client-side check; a non-image fails later inside `createImageBitmap` with a generic message.
- `api/test/e2e.mjs` line ~346 uploads `Buffer.from('avatar-bytes')` as the avatar. Once validation lands this must use `test/fixtures/photo.jpg`.

Out of scope (deliberately): deleting an avatar, cropping, avatars in the weekly recap image, avatar in `/invite/:code`.

## Global Constraints

- All web data access goes through the API (`web/lib/api.ts` / `api-server.ts`); supabase-js is auth-only in the web app.
- Client-component reads use TanStack Query; `useState` only for form fields and UI toggles.
- No new npm dependencies in either package.
- Keep the `photos` bucket private; avatars render only through signed URLs the API attaches as `avatar_src`.
- Avatar storage path stays `${userId}/avatar.jpg` (derived server-side, never client-supplied).
- Postgres constraint violations remain the validation layer for DB writes; file validation lives in the NestJS pipe layer.
- Match existing style: 2-space, single quotes in `api/`, double quotes in `web/`, comments explain *why*.
- Do not commit, push, branch, or run `drizzle-kit push`. No schema or migration changes are needed for this plan.
- Tests: `api/` → `npm test` (Jest), `web/` → `npm test` (Vitest). CI also runs `npm run lint:check` (api), `npm run lint` + `npm run build` (web).

## Review Focus

1. **A non-JPEG body posted straight to `POST /me/avatar`** (bypassing the client compressor) must get 400, never a stored unusable object. → Task 2 spec "rejects text masquerading as JPEG with 400".
2. **An oversized avatar body** must be refused before the handler runs (413), the same as entry photos. → Task 2 spec "rejects files over 5 MiB before the handler".
3. **A user with no avatar in a list that mixes users with and without avatars** (friends list, leaderboard) must still render an aligned, same-size placeholder, not a missing cell. → Task 4 Avatar fallback test; Task 3 e2e asserts `addressee.avatar_src === null` for the user without one.
4. **A signing failure** (storage unreachable) yields `avatar_src: null`; the UI must show the fallback, not a broken image. → Task 4 fallback test covers `src={null}`.
5. **Choosing a non-image file in the avatar picker** must not send a request, must show why, and must reset the input so the same file can be re-chosen. → Task 6 account-panel test.

// api/src/photo-upload.ts
import { FileTypeValidator, ParseFilePipe } from '@nestjs/common';
import { FileInterceptor } from '@nestjs/platform-express';

// One validation story for every image upload (entry photos, avatars): the
// web app compresses to JPEG under 500 KB, so anything else is a bypass.
export const PHOTO_MAX_BYTES = 5 * 1024 * 1024;

/** Multipart `file` field, refused with 413 before the handler if over the cap. */
export const photoFileInterceptor = () =>
  FileInterceptor('file', { limits: { fileSize: PHOTO_MAX_BYTES } });

/** 400 when the file is missing or its bytes are not a JPEG. */
export const jpegFilePipe = () =>
  new ParseFilePipe({
    validators: [new FileTypeValidator({ fileType: 'image/jpeg' })],
  });
```

import { StorageService } from './storage.service';

// constructor: replace
  constructor(
    @Inject(DB) private readonly db: Db,
    private readonly storage: StorageService,
  ) {}

// list(): replace the whole method
  /** Both sides carry a signed avatar so the friends page renders like every other user list. */
  @Get()
  async list(@UserId() userId: string) {
    const rows = await this.db
      .select({
        id: friendships.id,
        requester_id: friendships.requesterId,
        addressee_id: friendships.addresseeId,
        status: friendships.status,
        requester: { username: requester.username, avatar_url: requester.avatarUrl },
        addressee: { username: addressee.username, avatar_url: addressee.avatarUrl },
      })
      .from(friendships)
      .innerJoin(requester, eq(requester.id, friendships.requesterId))
      .innerJoin(addressee, eq(addressee.id, friendships.addresseeId))
      .where(this.participant(userId))
      .orderBy(desc(friendships.createdAt));
    const signed = await this.storage.sign(
      rows.flatMap((r) => [r.requester.avatar_url, r.addressee.avatar_url]),
    );
    const src = (path: string | null) => (path ? (signed.get(path) ?? null) : null);
    return rows.map((r) => ({
      ...r,
      requester: { username: r.requester.username, avatar_src: src(r.requester.avatar_url) },
      addressee: { username: r.addressee.username, avatar_src: src(r.addressee.avatar_url) },
    }));
  }
```

- [ ] **Step 3: Create the component**

```tsx
// web/app/avatar.tsx

// Square avatar at a fixed Tailwind size; a user without one gets their
// initial in the same box so lists stay aligned. Classes are listed in full
// because Tailwind only emits literal class names.
const SIZES = {
  5: "h-5 w-5 text-[10px]",
  7: "h-7 w-7 text-xs",
  14: "h-14 w-14 text-2xl",
} as const;

export default function Avatar({
  src,
  username,
  size,
}: {
  src: string | null | undefined; // signed URL from the API
  username: string;
  size: keyof typeof SIZES;
}) {
  const box = `${SIZES[size]} shrink-0 object-cover`;
  if (src) {
    // eslint-disable-next-line @next/next/no-img-element -- signed URL, remote patterns don't apply
    return <img src={src} alt="" className={box} />;
  }
  return (
    <span
      aria-hidden="true"
      className={`${box} inline-flex items-center justify-center bg-[var(--color-divider)] font-extrabold uppercase`}
    >
      {username[0]}
    </span>
  );
}
```

```ts
// Shared gate for the avatar picker and the log form. The API enforces JPEG
// and 5 MiB after compression; this catches the obvious mistakes before any
// decoding work and gives the user a reason instead of a decoder error.
export const PHOTO_MAX_RAW_BYTES = 20 * 1024 * 1024;

export function photoProblem(file: File): string | null {
  if (!file.type.startsWith("image/")) return "Choose an image file.";
  if (file.size > PHOTO_MAX_RAW_BYTES) return "That image is over 20 MB.";
  return null;
}
```
